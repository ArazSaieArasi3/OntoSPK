# Overview

OntoSPK organizes knowledge about software products while preserving distinctions between an intended specification, an actual realization and evidence about what occurred. A product can continue through changes to its versions and delivery arrangements; an execution record refers to a particular realized context rather than to the product in the abstract.

The conceptual model contains twelve local domains. External handles identify boundaries to independently governed subjects; a handle does not establish imported-class equivalence or approval by the external ontology owner.

The distribution provides three complementary representations: a native conceptual model, a bounded OWL theory and a relational reference implementation with finite-data admission controls. Each serves a different purpose. Their correspondences are documented explicitly rather than assumed to be lossless.
