Evaluation and reasoning

This is the preserved core specification or guide baseline. Ontology core v2.0.0 is unchanged; the accepted bounded FOL evidence is v2.0.6. Historical preparation labels and earlier test counts below retain their original context. Read the current formal verification method and version explanation and the evaluation overview. Reviewed diagrams and domains · Citation and evidence handoff · Current capability profile decision.

The original core evidence consists of finite synthetic controls and exact-source checks. It reports what was executed, the input baseline, tool versions, expected outcomes, observed outcomes and limitations.

Method Evaluated scope
Structural reconciliation 892 registered expressions compared with the native structure.
Combined admission 42 bounded population and admission controls.
Revision controls 146 regression and occurrence/history controls.
Competency questions 374 exact-answer comparisons across 56 contracts and 187 fixtures.
Project-owned rules 80 rule, applicability and adapter controls.
Upstream validator Direct execution of the 13 implemented class-rule functions.
OntoUML SDK Pinned-source serialization and fidelity controls.
OWL/HermiT 13 reasoner cases and four open-/closed-world contrast controls.

These denominators overlap and must not be summed as independent observations. Fifty-eight of the 71 declared upstream validator rules are unimplemented. The evaluated direct-call harness retains 54 warnings and reports no errors in its implemented functions. This does not constitute a complete upstream whole-model validation.

The execution receipt and method-specific reports record the accepted original core run. Command paths in the published receipt are normalized to repository-relative paths and named external-tool placeholders for portability; outcomes are not changed. Successful local execution and successful remote CI are separate statuses.

The earlier candidate's revision receipt included three checks against a pinned external Market snapshot. The public core does not redistribute that snapshot. Its current revision harness uses three synthetic RDF boundary checks with the same local non-conflation intent; these do not verify the external owner's current model. Compare execution receipts by source revision as well as by total case count.

The full recorded integration includes a finite SQL admission harness; this is a test of supplied synthetic records, not a public database distribution or a claim about a production implementation. The public ontology core excludes the physical database.

Independent semantic/domain review, external-owner acceptance and production deployment remain outside these results. See Limitations and Reproduce.

Later accepted evidence

The expanded evaluation records 71 HermiT scenarios and all 1,977 SHACL component occurrences. The FOL method explains the representative v2.0.6 finite pilot. The PC-01 decision adopts the concrete capability project profile with a declared reference deviation; it does not establish strict reference conformity. The current residual metadata account preserves 318 annotated-view findings, including 34 ERROR. These later reports supplement the original core results; they do not convert historical counts into current execution claims.
