Citation and publication evidence handoff

This page is the repository handoff for manuscript author review. It identifies the public core, later evidence increments, reproducible results and outstanding scientific limits. Proposed manuscript wording below is a draft for the authors; no manuscript file is edited or correspondence sent by publishing this handoff.

What to cite

Cite core v2.0.0 for the ontology model. Cite the exact evidence release when reporting its executed checks, and use that release's immutable tag/commit rather than a mutable branch or the current site route. The release record determines actual publication state. A source-prepared release plan is not a published release.

No DOI has been assigned in the current repository metadata or release records reviewed for this handoff. The root CITATION.cff describes the core. Release-specific v2.0.7 citation metadata identifies the documentation/diagram increment if that tag is actually published. No project-wide reuse licence has been selected; rights and third-party notices remain applicable. DOI registration (#29) requires an actual deposit service, rights/metadata review and a returned identifier; none is invented here.

Current ProductCapability / Mode decision

The subsequent PC-01 v1.0.0 profile decision resolves the project choice tracked in #48: retain the concrete actual-disposition class within an explicitly bounded project profile. The exact official documentation commit requires abstract Mode; the mismatch is disclosed and strict reference-profile conformity remains unclaimed. The decision and its source-bound structural/migration checks are a later repository increment; they are not retroactively part of the immutable v2.0.7 archive. The consolidated v2.0.8 sources include PC-01 explicitly.

Changing the flag alone would leave an abstract native leaf without concrete specializations. Introducing meaningful concrete subkinds would require domain justification and a reviewed migration. Current instance typing, bearer cardinalities, OWL mapping and native/FOL constraints therefore remain as released. The complete comparison, alternatives and reopening conditions are available on the decision page within this site. No author confirmation is outstanding for this bounded choice: the maintainer delegated it. Independent expert acceptance and full UFO conformity are still unestablished.

Proposed manuscript wording for author review

The following is a proposed availability/evidence statement, not an automatic replacement in the manuscript:

The OntoSPK ontology core and its versioned documentation and evaluation artifacts are publicly available in the project repository. The released evidence distinguishes native conceptual commitments, a bounded OWL profile, graph-validation contracts and a representative finite first-order verification pilot. Reported checks are tied to their exact sources and assumptions and do not establish complete semantic adequacy or independent expert acceptance.

For an IEEE-style reference to the core, the author can use:

A. Saie Arasi, “OntoSPK: An Ontology for Software Product Knowledge,” ontology core, ver. 2.0.0, 2026. [Online]. Available: https://github.com/ArazSaieArasi3/OntoSPK/releases/tag/v2.0.0. Accessed: Oct. 24, 2026.

Use a separate exact evidence-release reference when citing specific executed results. Preserve the manuscript's existing author/affiliation style, page limit, figure selection and approved wording. Numeric implementation inventories on this handoff page do not authorize adding them to the manuscript.
